# SereinOS Interaction Model

## Core Principle

The primary interface of SereinOS is Serein.

The user should interact with Serein rather than directly interacting with applications, menus, or the desktop.

---

# Interaction Philosophy

Traditional Operating Systems:

User
→ Desktop
→ Application
→ Task

SereinOS:

User
→ Serein
→ Task

Serein decides how the task should be completed.

---

# Boot Experience

When the computer starts:

Serein appears first.

The desktop remains hidden.

The user is greeted by Serein.

Serein becomes immediately available for conversation and task execution.

---

# Desktop Philosophy

The desktop is a secondary interface.

The desktop should remain hidden unless:

* The user requests it.
* Visual interaction is required.
* A task cannot be completed conversationally.

---

# Invisible Actions

Whenever possible, Serein performs actions without opening visible applications.

Examples:

User:
"Play my study playlist."

Result:
Music begins playing.

---

User:
"Move my DSA notes into Semester 5."

Result:
Files are moved.

---

User:
"Open Chrome."

Result:
Chrome launches.

---

# Visual Actions

Applications may appear when visual interaction is necessary.

Examples:

User:
"Show me my notes."

Result:
File manager opens.

---

User:
"Edit this image."

Result:
Image editor opens.

---

# Conversation First

Voice and text are first-class interfaces.

Menus are secondary.

Buttons are secondary.

Windows are secondary.

Conversation is primary.

---

# Serein's Role

Serein acts as:

* Assistant
* Companion
* System Interface
* Task Executor
* Knowledge Source

Serein is not an application.

Serein is the operating experience.

---

# Long-Term Goal

The user should feel like they are interacting with Serein rather than interacting with an operating system.
